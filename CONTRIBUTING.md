# Contributing to the CodeFamily Cloudflare Web Development Guide

Thank you for helping improve this guide. Contributions should make the instructions clearer, safer, more accurate, or easier to reproduce.

## Before you contribute

1. Read the relevant page and the linked official Cloudflare documentation.
2. Confirm the behaviour you are describing in the current dashboard, CLI, or runtime where practical.
3. Search existing issues and pull requests to avoid duplicating work.
4. For significant changes, open an issue first to discuss the proposed direction.

## Good contributions

- Fix an incorrect, outdated, or confusing instruction.
- Add a missing prerequisite or troubleshooting step.
- Improve accessibility, navigation, spelling, or examples.
- Add a minimal, reproducible example that has been tested.
- Clarify when instructions differ between Pages, Workers, frameworks, or deployment methods.
- Update links when official documentation moves.

## Reporting a problem

When opening an issue, include as much of the following as applies:

- The guide page or file path.
- The Cloudflare product involved (for example, Pages, Workers, R2, or D1).
- The framework and relevant tool versions.
- The steps to reproduce the issue.
- Expected behaviour and actual behaviour.
- A redacted error message or screenshot, if useful.
- A link to the relevant official documentation.

**Never post secrets or personal data.** Remove account IDs when not needed, access tokens, API keys, passwords, private keys, session cookies, and sensitive production logs.

## Pull request workflow

1. Fork the repository.
2. Create a focused branch for your change.
3. Make the smallest useful change.
4. Check spelling, Markdown links, headings, code formatting, and relative paths.
5. Test commands or deployment steps you changed. Clearly label anything you could not test.
6. Open a pull request describing the problem, solution, and verification performed.
7. Respond to review feedback and update the pull request as needed.

## Writing standards

- Prefer plain language and short, direct steps.
- Explain prerequisites before commands.
- Use descriptive headings and meaningful link text.
- Do not present assumptions as verified facts.
- Prefer official Cloudflare documentation for product behaviour and identify when information was last checked.
- Avoid publishing secrets, unverified claims, or instructions that weaken security.
- Keep examples small and reproducible.

## Scope and review

Submitting a contribution does not guarantee acceptance. Maintainers may ask for changes or close contributions that are out of scope, unsafe, duplicative, or not sufficiently verified.
